# IMP-ROLLBACK001 Automatic Safe Rollback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a data-preserving rollback primitive so a technically failing candidate transaction path can fall back exactly once to the stable path with the same transaction identity, without rewinding canonical history or duplicating business effects.

**Architecture:** Add a small generic rollback executor under `src/continuity/rollback.ts`. The Worker keeps the existing stable transaction route but passes it through the rollback executor using the already-resolved continuity path. Candidate execution remains unavailable in production; deterministic tests inject candidate executors to prove pre-commit fallback, post-commit reconciliation through `IMP-COMMIT001`, exact replay, business-result handling, and project isolation.

**Tech Stack:** TypeScript, Cloudflare Workers Durable Objects/SQLite, Dropbox V2 canonical commit records, Vitest with `@cloudflare/vitest-pool-workers`, deterministic Dropbox fault injection.

**Spec:** `docs/superpowers/specs/2026-08-24-imp-rollback001-design.md`

## Global Constraints

- Production continuity mode remains exactly `stable` throughout this package.
- Rollback changes execution path only; it never rewinds Dropbox, snapshots, events, receipts, revisions, decisions, deliverables, or accepted work.
- Stable fallback always receives the exact original `Transaction`, including the same `transaction_id` and `project_id`.
- Valid business receipts with status `committed`, `rejected`, or `conflict` never trigger fallback.
- Only technical candidate failures trigger one stable fallback; stable failure is never recursively routed back through candidate.
- Project isolation must be preserved: a failure for one project must not mutate another project.
- `/v1/transactions` continues returning the existing `Receipt` contract; no user command, header, migration instruction, or version selector is introduced.
- Existing V2 commit-record reconciliation from `IMP-COMMIT001` remains the durable source of post-commit recovery truth.

- [ ] **Step 3: Implement the minimal executor**

Create `src/continuity/rollback.ts` with these public types and behavior:

```ts
import type { ContinuityPath } from "./policy";
import type { Receipt } from "../domain/receipt";
import type { Transaction } from "../domain/transaction";

export type TransactionExecutor = (transaction: Transaction) => Promise<unknown>;

export interface RollbackExecution {
  receipt: Receipt;
  selected_path: ContinuityPath;
  final_path: ContinuityPath;
  fallback_occurred: boolean;
  candidate_failure?: "technical" | "malformed_result";
}

export interface RollbackExecutionInput {
  selectedPath: ContinuityPath;
  transaction: Transaction;
  stable: TransactionExecutor;
  candidate?: TransactionExecutor;
}

export async function executeWithRollback(input: RollbackExecutionInput): Promise<RollbackExecution> {
  if (input.selectedPath === "stable") {
    return {
      receipt: requireBusinessReceipt(await input.stable(input.transaction), input.transaction),
      selected_path: "stable",
      final_path: "stable",
      fallback_occurred: false
    };
  }

  let candidateFailure: RollbackExecution["candidate_failure"] = "technical";
  try {
    if (!input.candidate) throw new Error("Candidate executor unavailable");
    const value = await input.candidate(input.transaction);
    const candidateReceipt = businessReceiptOrNull(value, input.transaction);
    if (candidateReceipt) {
      return {
        receipt: candidateReceipt,
        selected_path: "candidate",
        final_path: "candidate",
        fallback_occurred: false
      };
    }
    candidateFailure = "malformed_result";
  } catch {
    candidateFailure = "technical";
  }

  return {
    receipt: requireBusinessReceipt(await input.stable(input.transaction), input.transaction),
    selected_path: "candidate",
    final_path: "stable",
    fallback_occurred: true,
    candidate_failure: candidateFailure
  };
}
```

Implement `businessReceiptOrNull` so a receipt is accepted only when it is an object with `schema_version === "1.0"`, matching `transaction_id`, matching `project_id`, status in `committed|rejected|conflict`, and non-negative integer `previous_revision`/`new_revision`. `requireBusinessReceipt` throws `Error("Stable executor returned an invalid receipt")` when validation fails.

export async function executeTransactionWithContinuity(
  env: Env,

  const status = continuityStatus(env.PROJECT_OS_CONTINUITY_MODE);
